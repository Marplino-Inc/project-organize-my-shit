# Organize 0.2.0

Tags now have a name and value (or explicit null). Projects define default tag sets which appear on
the project and all work items. Items can override a value or turn Override off to inherit again.
Copy another project's default set from the project editor. Filters, dashboards, reports and agents
use effective tags.

The new Palette selector offers Organize, Shiny Mint, Viridis, Brewer Garden and Material Blue.
Each works with Light, Dark or System. Preferences includes swatches and source links. Your existing
palette/mode remains selected until you change it.

## Upgrade

Stop the previous app before launching this version. First launch automatically backs up the old
database beside it as `*.pre-v0.2.0-*.db`, then migrates its tags. Legacy project labels become
null-valued defaults; legacy item labels become null-valued local pairs. Other records remain intact.
To revert, stop this app and open the backup with the old version; do not use 0.1.0 on the migrated file.

Agents must use object-shaped `tags` and project `tag_defaults`; the CLI now returns read-only
`effective_tags`. See [agent interface v2](../agent-interface.md). New exports use snapshot v2;
existing snapshot v1 files still import.

## Download and run

Extract the Windows source ZIP, install uv if needed, and double-click Start.cmd. Python dependencies
download on first launch; normal use runs locally at `http://127.0.0.1:8765`. Data stays in
`%LOCALAPPDATA%/ProjectOrganize`, outside the extracted source folder.

This remains a browser-based local application with source and launchers, not a standalone executable
or signed installer. See [development status](../development-status.md) for tested behavior and limits.
